CURRENT BEHAVIOR:
In `_syncStarterMeals(AppDatabase db, {bool isManual = false})`:
1. Matches remote and local starter meals strictly by `name.trim()`:
   ```dart
   remoteMap[name] = doc;
   ...
   localMap[l.name.trim()] = l;
   ```
   If an administrator renames a starter meal in the cloud (or fixes a typo in its name), the sync loop thinks the local meal was removed from the cloud, and in auto-sync it executes:
   ```dart
   if (!isManual) {
     await db.mealsDao.deleteMeal(l.id);

   ```
   This permanently deletes the local meal!
   Because `meal_history` cascades with `ON DELETE SET NULL`, all past cooking history records for this meal have their `meal_id` set to NULL, and user favorites/notes are completely destroyed.
