     try {
       // 1. Detach old meal from cloud
       await _mealsDao.updateMealCompanion(oldLocalId, const MealsCompanion(

   Problem:
   The old meal is detached from its cloudId BEFORE `_createCompanion` (which performs network image download via `MealImageLocalizer`).
   If the network download fails, times out, or throws an error, the old meal has already lost its cloud link forever, and the new meal is never created.
   Furthermore, steps 1 and 2 are not executed inside an atomic database transaction.

   Problem:
   `downloadAsNew` is called fire-and-forget without `await`.
