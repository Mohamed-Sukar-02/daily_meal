
### MealScreen sync mark: spec verification + three convergence fixes (Sep 24)
- **Requested:** make the app-bar cloud mark beside the heart switch download/upload/sync, orange on a detail difference, tapping it opening a sync-diff window. That behaviour already shipped in `37e67fa` — this pass VERIFIED it and fixed what the verification broke open.
- **Verified:** `meal_sync_state_test.dart` 4/4 → 6/6; a scratch render harness (deleted after) PNG-dumped the upload mark (gold), the synced mark (accent) and the opened window, and hard-asserted the differs colour is literally `0xFFFFA53C`; full suite 114/114, analyze clean on every touched file.
- **Fixed — notes never copied (`discovery_providers.dart::_createCompanion`):** `mealCloudDiffs` compares notes, but neither `downloadMeal` nor `updateMeal` ever wrote them — a downloaded meal with cloud notes landed permanently orange, and "Update from cloud" could not clear a notes-only diff. One line + `test/unit/meal_sync_notes_test.dart` (red before, green after).
- **Fixed — phantom category diff (`cloudCategory`):** the deployed rules vocabulary includes `soup_stew`/`vegetarian`, and `AppConfigSyncService._mapCategory` stores them as real local enums — but `cloudCategory` had no branches for them, so every starter-synced soup/vegetarian meal read as differing, and "Update from cloud" flattened its category to `egyptianTraditional`. Added both cases + `test/unit/cloud_category_mapper_test.dart` (all seven deployed tokens).
- **Fixed — false success toast (`meal_screen.dart::_downloadCloudMeal`):** a failed insert returned null but still toasted "Downloaded". Now toasts the new `mealDownloadFailed` string instead.
- **New coverage:** the sync window's two buttons are now exercised end to end against an in-memory vault (update rewrites the row, keep leaves it); needed `SharedPreferences.setMockInitialValues({})` because `MealsDao.insertMeal` consults the starter blacklist and its platform call never answers under the test binding.
- **Audit trail:** a 26-agent adversarial workflow (state-selection / diff engine / window / tests) confirmed exactly the two majors above and refuted the suspected suspects (Arabic plural false-diffs, autoDispose staleness, empty-diff window opening). Documented-intentional remain: offline/missing cloud doc reads as plain sync; photo and createdAt excluded from the diff; the busy spinner is driven by the global discovery notifier.
